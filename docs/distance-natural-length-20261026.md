## 原因と変更

| 調査結果 | 対応 |
| --- | --- |
| ランドマーク間距離は毎回計算していたが、手の尺度に画面固定の上限・下限、爪長に画面高18%の上限があった | 画面固定の制限を除去。指先・DIP・PIPの投影距離と掌の比率に応じて全指を再計算する。形状を守る掌比率の範囲は残す |
| 位置・幅・高さを画面座標で別々に平滑化し、手全体の移動・拡縮でも追いつくまで遅れた | 掌の中心・向き・尺度による相対座標で指固有の動きだけを平滑化し、現在フレームの掌で描画座標へ戻す |
| 画面上の大きさをそのままフィルタに入れ、小さい小指と大きい親指で割合変化への応答が違った | サイズを対数で平滑化。位置・サイズ・回転のフィルタを分離したまま、サイズはminCutoff=2.5 / beta=2とする |
| 画像探索は推定爪長の2倍までで、長い爪先が領域外になった | 標準補正が失敗した指だけ、爪先方向に探索を延長。長さ1.7〜3.25倍、根元近傍、横ずれ、色境界、複数しきい値の一致を要求する |
| 画像補正のキャッシュや手動補正で高さ倍率が2倍までに切られていた | 高さ倍率を最大4倍へ拡張。キャッシュから適用し直す際に、せっかく合わせた長い爪が短く戻るのを防ぐ |
| 平均的な自爪の長さしか選べなかった | 「基本」に自動／自爪短め／自爪標準／自爪長めを追加。「仕上がりの長さ」と区別し、写真・カメラ両方へ反映する |

`NailPose.x/y`は根元。長さの目安は根元と幅を変えず、爪先側の長さだけを0.84／1／1.45倍にする。
画像で境界を採用できるときは、その長さを優先する。これは実寸測定でも学習済み爪AIでもない。
指別の幅・長さスライダーも近距離の大きさを扱えるようにした。設定は既存localStorageへ保存し、履歴・お気に入りから戻るときにも長さの目安を引き継ぐ。
根元方向の手動補正の尺度は、延長後の爪長ではなく元の爪床長として保持する。長さの目安を切り替えても、保存した根元補正まで拡大されないようにした。

ライブの設定変更ではフィルタと画像補正キャッシュのみリセットする。カメラstreamとMediaPipeは再起動しない。
親指・小指は既存の専用幾何係数、親指の横補正を維持し、全指に相対座標追尾を適用した。
今回の評価では専用係数の変更を正当化できなかったため、一律に位置を動かす変更はしていない。
zは指先と関節の相対差による既存の遠近補助だけに使用。カメラからの距離をメートルで得たわけではない。

## 採用しなかった変更

標準探索まで広げた試作では、実画像のIMAGE平均楕円IoUが0.310→0.302に悪化した。
その試作は採用せず、従来の標準補正が成立した場合はその結果を維持する方式にした。
追加探索は明瞭な長い候補だけを採用し、それ以外は幾何推定と選択した長さの目安へ戻す。

## 再現テスト

`scripts/check-distance-tracking.mjs`を`npm test`に追加した。

- 5本の指、0.35〜3.2倍の手の尺度、左右反転、回転、上下左右移動。
- 9:16 / 1:1 / 4:3 / 16:9の座標系。近づいたときの幅・高さが同じ倍率で変化する。
- 掌を固定した指固有の微振動の抑制、小さい爪と大きい爪で同じ割合のサイズ応答。
- 既知の長い爪の画像、根元・先端・幅・高さ、親指と小指、反転、補正キャッシュの倍率維持。
- 実際のtracking loopをモックMediaPipeで動かし、IMAGE/VIDEO双方の長さモード、根元固定、モデルとloopの多重作成なし、stream維持を確認。

理想的なランドマーク列（60フレーム、50ms間隔）で旧追尾と比較した結果:

| 指標 | 旧追尾 | 相対座標追尾 |
| --- | --- | --- |
| 元の幾何推定に対する中心の平均遅れ | 3.18px | 0.001px未満 |
| 元の幾何推定に対する幅・高さの平均割合誤差 | 3.86% | 0.001%未満 |

これは**理想ランドマークに対する数学的な応答**であり、実際の爪に対する誤差ではない。掌の測定誤差、カメラの遅延、指の曲げ伸ばしによる誤差は含まない。
既知の長い爪（22×70px）では、初期推定14×22pxから22.34×70.86pxへ補正。根元誤差0.78px、先端誤差0.50px。ただし単純な色の楕円を使った合成画像である。

## 実画像の回帰評価

既存ローカルのCC0爪マスク付き28枚を使用し、同一の現行MediaPipeランドマークで旧パイプライン全体と比較した。
元画像・画素データをpublicやGitへ追加していない。詳細は`evaluations/distance-fit-image.json`と`distance-fit-video.json`。

| 指標 | IMAGE 旧→新 | VIDEO入力 旧→新 |
| --- | --- | --- |
| 対応づけた爪 | 137 | 135 |
| 中心誤差平均 | 12.45→12.45px | 12.80→12.80px |
| 楕円近似IoU平均 | 0.310→0.310 | 0.311→0.311 |
| 幅の平均絶対割合誤差 | 40.44→40.44% | 39.81→39.81% |
| 長さの平均絶対割合誤差 | 25.44→25.44% | 23.03→23.03% |
| 近似根元誤差平均 | 14.90→14.90px | 14.71→14.71px |

デフォルト自動モードでは、この実画像集合に追加で長い候補を採用しなかった。**既存精度は維持したが、実写の静止位置精度が向上したとは言えない。**
IMAGEでは細長いマスク（主軸長／幅1.8以上）27件、その他110件も分けて確認し、双方で結果は不変。
この分類は見かけの縦横比であり、「長い自爪」という人手ラベルではない。親指27件・小指28件も不変で、親指の中心誤差平均18.75px、IoU 0.157は引き続き課題。

対応づけは旧幾何推定に固定した貪欲な連結成分対応。IoUは楕円近似。
根元はマスク重心・主軸長から近似し、実際の甘皮の正解ラベルではない。
VIDEOは各静止画像を3回入力した評価で、実際に手が動く録画の位置精度とは異なる。独立した人物別テストセットでもない。

## 負荷と残る課題

画像補正だけのNode CPUベンチ（28枚×3回、ウォームアップ後）は中央値16.30→23.61ms、p95=22.07→33.21ms。
長い爪の追加探索には負荷が増える。既存の150ms補正キャッシュ、640px画素処理上限、処理時間込みの推論頻度調整は維持。
ソフトウェアGPUのheadless開発テストでは処理時間203〜341ms、検出約3.0〜3.5fps。スマホ速度の証拠にはならず、FPS向上は主張しない。

実機iPhone Safari / Android Chrome / USBカメラでの実際の距離変更・曲げ伸ばし、低照度、遮蔽、長い透明な自爪の境界は未検証。
現在の方式はランドマーク推定＋条件付きの色境界補正であり、全ての爪を正確に認識できるわけではない。
人手で根元・先端をラベルした実写動画、特に親指・小指と長い自爪を増やすことが次の精度評価に必要。

`npm run lint` / `npm run typecheck` / `npm test` / `npm run build`は成功。47ページの生成を確認。
公開設定・広告・GA4・ads.txt・旧HTML版は変更していない。GitHubへpushしない。
