# 爪密着精度：2026-10-30

## 結論と範囲

基準コミットは `b1ed43d`。変更前の28枚分の評価を保存した上で比較した。位置・幅・長さの画像補正を限定的に増やし、相対補正の急変確認を追加した。**完全な爪への密着は未達。特に親指の改善は小さく、根元・回転の正解ラベルも不足している。**

本番変更は画像補正とその時間的一貫性、開発用診断のみ。MediaPipeの設定・自己ホスト、指別の幾何推定係数、One Euro Filter、手の甲/手のひら判定、可視性しきい値、Canvasのデザイン形状・質感、画面構成、カメラライフサイクル、保存、SEO/GA4/AdSense/ads.txtは変更していない。新規ライブラリ・新規AIモデル・サーバーへの画像送信は追加していない。pushしない。

## 1. 調査で確認したこと

- `NailPose.x/y`は爪中心ではなく**根元**。指先とDIP/PIP、手全体の大きさ、限定的な奥行き補正から軸と幅・長さを算出。幅はフレーム幅基準、長さはフレーム高さ基準で、物理的な距離計算ではアスペクト比を適用している。
- MediaPipeの21点は爪輪郭そのものではない。親指の斜め方向・小さい爪では、根元・爪床の幅/長さがランドマークだけからは確定しない。単一の固定倍率で解決する問題ではない。
- `containRect`で元映像の比率・余白をCanvas描画に反映し、操作の座標も`pointInSource`で同じ領域へ戻す。反転は表示座標と元画像サンプルを分離している。今回、二重反転・全体の縦横比ずれ・手動補正の二重適用は再現しなかった。
- 画像解析はネイルを描く前のフレームを最大640pxに縮小して使用。手のローカル軸に沿うROIで色領域を探索するが、肌との低コントラスト、反射、模様、背景との連結で失敗する。IMAGE28枚では候補の棄却回数が area 5,582、patch-edge 3,974、fill 381、contrast 276。これは**候補数**であり、失敗画像数ではない。原因を照明別にラベル付けした測定ではない。
- 標準探索が失敗した場合にだけ長い自爪の追加ROIを使う既存処理は維持。自爪の長さ設定と、描画デザインの延長は別物。延長時に根元を移動させない既存処理も維持した。
- 相対画像補正の150msキャッシュは元の指のスケールに追随する一方、新たな画像補正が突然別の領域へ切り替わることは防いでいなかった。位置フィルタの変更ではなく、画像補正そのものの確認を追加するのが今回の最小範囲。

## 2. 採用したアルゴリズム

### 境界支持付きの補助候補

既存の色領域フィットに成功した指は変更しない。失敗した指だけ、現在の推定爪を中心とした相対座標・相対サイズの範囲で楕円状の内外24サンプルを比較する。幅と長さは独立に探索し、根元と**左右両側**の境界支持、内部の色のばらつき、周囲の色の整合性を要求する。小さすぎる爪は試さず、条件を満たさなければ従来推定へ戻る。

切り抜き済みの爪輪郭を検出したとは扱わない。confidence=0.7は制御用のヒューリスティックで、校正された正答確率ではない。絶対輪郭・クリップは生成しないため、これ単独では横向き/手のひらの部分描画を許可しない。手の甲の既存表示も画像補正失敗で消さない。

### 相対補正の時間的一貫性

画面上のピクセル移動ではなく、指の横/縦方向の相対オフセットと幅/長さの倍率・角度を比較する。大きな変更は短時間に2回の整合した観測を必要とし、それまでは直前の相対補正を現在の指に適用する。カメラへの接近・遠ざかり・移動そのものは抑制しない。450ms以上前の履歴、時間軸の逆行、鏡像/比率変更、dispose時には古い確認を引き継がない。

保留中は古い絶対輪郭を渡さない。部分可視の爪は常に最新の輪郭を必要とするため、この保持処理の対象外とした。既存のOne Euro Filterは変更していない。

## 4. 評価方法と制約

- 主データ：既存の[nails-segmentation-dataset](https://github.com/vpapenko/nails-segmentation-dataset)、ローカルのCC0評価用28枚。IMAGEでは137本、VIDEO相当では135本のマスク成分を対応付けた。最長辺640px。両版に同じランドマーク・同じマスクを使用。
- VIDEO相当は各静止画をMediaPipe VIDEOモードへ3回渡した結果。**連続動画でも、時間的一貫性ゲートを通した精度測定でもない。** 時間ゲートは合成連続フレーム・ブラウザ統合試験で別途確認した。
- 補助データ：既存の[Roboflow fingernail_detetction](https://universe.roboflow.com/fingernail/fingernail_detetction)の90枚。エクスポートREADMEはPublic Domain、COCO Segmentation。矩形だけではなく複数頂点のポリゴンだが、爪床の根元や指IDの正解はない。640×640へのstretch済み。IMAGEは34枚/147本、VIDEO相当は49枚/216本が検出・対応できた。未検出56枚/41枚を誤差ゼロと数えていない。主データとの重複例があり、既存の開発用データでもあるため**独立した未使用テストセットではない**。
- マスクの連結成分と、変更前の粗推定の中心距離による貪欲対応を固定。指別の表は推定指IDであり、正解指IDが保証された評価ではない。隣指との対応ミスの可能性は残る。
- 「楕円IoU」はポーズの楕円とマスクの重なりで、生成デザインの写実性ではない。追加で、本番の`buildNailPath`をChrome Canvasへ実描画し、alpha>=128のシルエットIoUも測った。陰影込みの最終画像の美観評価ではない。
- 中心はマスク重心、幅/長さ/角度はPCAと投影範囲から算出。近似根元は重心からPCA長の半分を戻した点で、軸の符号は基準推定へ合わせる。**解剖学的な根元/甘皮の正解ラベルではない。** 丸い爪の角度は不安定なので、縦横比1.35以上のみ角度評価する。
- 添付スクリーンショットは既に仮想ネイルが重なっているため、ピンク部分を正解の爪輪郭として使っていない。今回の画像に専用係数を合わせていない。
