## 2. 確認した遅さと測定方法

自己ホストのWASM取得後、7,819,105バイトの `.task` を非圧縮で取得していた。10Mbps制限下ではモデル転送だけで約6.41秒。これが「映像は出るが自動試着を待つ」時間の大きな、再現できる要因だった。WASM自体は既にHTTP圧縮されており、初回の転送時間は約2.90秒。

ホーム・試着の初期表示の遅さを、このモデル転送で説明してはいけない。カメラ開始前のMediaPipeアセット要求は両版とも0。初期表示側の明確なボトルネック/改善は今回確定していない。以前の「3/10」という利用者評価を今回のラボ値で否定しない。

測定条件：production `next build` + `next start`、ローカル2ポート、Chrome headless、390×844、ダウンロード10Mbps/遅延80ms。ナビゲーションはCPU4倍減速、カメラはCPU等倍/SwiftShader。GA/広告のみCDPで遮断。ブラウザは新規context、サーバーは起動済み。画像は権利情報付き既存の手の写真を640×480のCanvas.captureStreamへ流す。**実カメラ・連続実写動画・iPhone/Android実機ではない。** OSのカメラ許可待ちは含まない。

最終版の前後各3回を `前1→後1→後2→前2→前3→後3` の順に逐次実行。各contextで初回と再読込を測定。基準版はgit archiveで分離し、依存は共有、MediaPipe JSローダーの改行だけ作業版と同じバイト列へ揃えた（内容同一を検査）。測定中に他のテスト/buildを同時実行しない。

「最初の5本」は、検出成功後かつ実CanvasのCSS opacity/globalAlphaが正の場合の5本分の描画呼出を観測した代理値。描画前の透明な初期ポーズを数えない。初期の試作計測では透明な5本を誤って数えていたため、そのfirst-five値は**破棄**した。最終JSONは修正後の反復測定のみ。ブラウザの実際のpaintや人の目による確認時刻と同一とは仮定しない。

Playwrightのroute()はHTTPキャッシュを無効化するため、速度計測には使わずCDPの第三者URL遮断を使用。機能テストでのroute()による画像/権限等の模擬とは分離する。

## 4. 実装と見送った案

`force-static` のRoute Handlerで、**build時に一度だけ**既存モデルをgzip圧縮。元のSDK URLはbeforeFiles rewriteで維持する。通常のgzip対応Accept-Encodingに限って圧縮表現を返し、identity/gzip禁止時は元のpublicファイルへ戻す。Content-Encoding/Content-Length/Vary/ETagを付与する。URL・モデルの中身・認識処理は不変。キャッシュ寿命max-age=0を維持し、圧縮応答にはmust-revalidateを明示する。長期immutableキャッシュは追加せず、更新時の古いモデル残留を避ける。今回新しいライブラリ/AI/モデルファイルは追加しない。

| 候補 | 採用判断 |
|---|---|
| プリセット一覧の遅延mount + memo | 事前比較で閉じたDOM83→0。ただし試着のlong-task超過時間中央値248→256ms、LCP1.172→1.120秒もばらつきが重なる。本番変更から取り除いた |
| SDKの追加遅延ロード | カメラ開始後の待ち増加を安全に否定できないため未採用 |
| 推論頻度削減・輪郭処理間引き・Worker化 | 実機の精度/速度比較がない。現在のiPhone復旧処理を優先し未実装 |
| 長期キャッシュ/URLの変更 | 将来のモデル更新と整合するバージョン管理が必要。今回の範囲から外す |
