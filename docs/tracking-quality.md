# 爪認識・追尾品質の改修記録（2026-10-24）

## 調査と実装

画面構成、Next.js App Router、MediaPipe自己ホスト、外付けWebカメラ、Canvasの仕組みを維持。
Google AdSense、GA4、ads.txt、ガイド記事、広告枠・除外エリアのコードは変更していない。

| 問題 | 改修 |
| --- | --- |
| 高さ制限のある縦長プレビューで、映像の余白とCanvas座標が一致しない | contain表示領域を共通計算し、描画・ドラッグ双方に適用。プレビューの大きさ変更もResizeObserverで反映 |
| 爪推定に指の奥行きが反映されない | DIP→指先の投影・奥行きから控えめに長さ補正。親指・小指の専用係数を維持し、縮みすぎを制限 |
| 左右反転時に薬指・小指の横補正の方向が一致しない | 横補正も反転し、全指の中心・サイズの対称性をテスト |
| フレーム依存のEMA、指の一時的な飛び、手の左右ラベルの変化 | 実時間のOne Euro Filterを位置・サイズ・角度に別設定。角度を連続化し、単独指の大きな飛びを2フレーム保留。高信頼の左右変更は3フレーム確認後にリセット |
| 認識喪失後も爪が残る | 短い欠落を120ms保持し、300msでCanvasをフェード。表示側にもopacity遷移を設定。長い欠落の復帰時は古い位置から補間しない |
| 推論開始時刻で喪失判定すると重い推論後に誤ってlostになりうる | 喪失判定は推論結果の受信時刻で統一 |
| 静止画認識が共有モデルをIMAGE/VIDEO間で切り替える | IMAGE/VIDEOモデルを各1個ずつ遅延初期化・再利用し、画面離脱時に解放。初期化失敗時のキャッシュ破棄とGPU→CPU fallbackを維持 |
| 非同期テクスチャが古い描画を再開する | I/O完了前にCanvasの状態を変更せず、世代確認後に全指を同期描画。カメラではテクスチャ待ち中も色・位置・フェードを描画 |
| 自動補正が固定量の移動・縮小を繰り返す | 写真は再認識。動画は最新の認識位置へ戻し、手動補正をクリア。認識できない場合は成功扱いにしない |
| カメラ追尾が手動調整を毎回上書きする | 指に対する相対的な横・縦補正、幅・長さ倍率、角度を保存。手の回転や距離変化に追従し、撮影時にも調整を引き継ぐ |
| 幅変更が長さを強制変更し、角度の操作範囲も不足する | 幅・長さを別操作にし、角度は±180度に対応 |
| 毎検出のReact更新とlocalStorage書き込み | 描画は最新poseのrefを読み、設定UIの更新を150msごとに制限。写真の保存は400ms debounce、カメラ補正の保存は手動操作時だけ |
| 推論負荷の計測や調整がない | カメラのpresentedFrames、描画FPS、推論FPS・時間を開発ログへ記録。推論は最大20Hz、長辺960px、重い場合は640px・間隔66〜100msへ変更。推論後にも休止時間を確保 |
| ベタ塗り、硬い線状ハイライト、根元の色の違和感 | 根元を薄くなじませ、曲面の柔らかな反射と控えめな影を追加。24×24pxの手の領域から明るさ・暖色度を最大4Hzで推定。読めない画像では標準値へfallback |

## 検証方法と限界

### 静止画

合成ランドマークで5本の根元、親指・小指、指の曲がり、奥行き、反転、距離変化、320/390/1280pxのcontain座標を検証。
Chromeで既存の `design_020.jpg` をアップロードし、自己ホストされた実際のMediaPipeによる手認識とPNGダウンロードを確認。
爪中心や輪郭の正解ラベルはないため、実写の位置誤差・IoUは未計測。

### 動画

MediaPipeをモックした実際のトラッキングループで、10秒の欠落・復帰、カメラ切替、VIDEO/IMAGE分離、例外時の停止・モデル解放を検証。
合成時系列では、上下・左右移動、急移動、静止揺れ、古い時刻、単独指の飛び、左右ラベルの変更、短時間保持・フェード・復帰、手動補正の追従を検証。
描画テストでは古いテクスチャ結果の破棄、Canvas状態の解放、長さ変更時の根元固定、欠損テクスチャのfallbackを検証。

Chromeでは、既存画像を少し左右に動かすCanvasのcaptureStreamを模擬カメラに接続し、実際のMediaPipe VIDEO認識・指別補正保存・認識喪失と復帰・撮影を確認。
これは実際に指を曲げる録画やUSBカメラの実機テストとは異なる。iPhone Safari、Android Chrome、物理カメラ、OSの共有シートは未確認。
広告・GAへの外部通信はこのブラウザ検証だけ遮断した。

### 数値

合成信号（位置ノイズ振幅0.16ポイント、15/20/30Hz）では、静止時RMSは入力0.1081〜0.1141から0.0218〜0.0302へ減少し、一定速度時のフィルタ単体の平均遅れは18.3〜18.5ms。
これはカメラの遅延・位置誤差・端末のFPSを示す値ではなく、旧版との実機比較でもない。

ヘッドレスChromeでSwiftShaderを明示した検証では推論が約185〜475msと遅く、当初の描画は約5FPS。
推論後に休止を入れた別試行では描画約11FPS、推論約3〜4FPSを観測した。条件・実行タイミングが同一ではないため改善率として扱わない。
実端末でのFPS向上や「プロ品質」は断定しない。

## 次のフェーズ

1. iPhone Safari・Android Chrome・USBカメラで、静止/移動/指曲げ/近遠/左右/逆光/遮蔽の録画を用意し、根元・中心の位置誤差を爪幅で正規化して計測する。
2. 推論は依然メインスレッドで同期実行される。低性能の実端末でも長いブロックが確認されたら、フレーム1枚だけを転送・古い結果を破棄するWorkerを別フェーズで導入する。今回のSwiftShaderだけで実機のGPU/CPU性能は判断しない。
3. MediaPipeランドマークは爪床の推定にのみ使用する。爪そのものへの密着には爪専用セグメンテーションを追加し、指ROIごとのマスクと境界・根元を評価する。学習データの権利・肌色・照明・角度の偏り、人物/撮影単位でのtrain/validation/test分割、マスクIoUに加えて境界誤差・動画でのちらつきも確認する。
4. 爪マスクが曖昧なフレームでは今回の幾何推定・手動調整へfallbackし、輪郭を正確に認識したように表示しない。
