# 緊急修正：手検出成功時の全ネイル消失（2026-10-30）

## 結論

`b2ad626`で導入した可視性制御の回帰を、実画像から得た検出データと制御した時間系列で再現した。正常版`531be1b`の配置・画像補正式は維持し、新しい可視性制御の「world不一致による全面棄却」「不明＝不可視」「推論間隔による繰り返し初期化」を修正した。サイト全体のロールバックは行っていない。日本語SEOの`f693895`も維持。

今回のメッセージには新しいスクリーンショットの画像ファイルを確認できなかったため、ユーザーの実機フレームでどの分岐を通ったかは未取得。ただし、同じ「手検出成功・手の甲・5本とも非表示」を既存のCC0実画像のランドマークで再現し、同じ入力で改善を比較した。実機そのものの修理完了や全条件での完璧な爪可視性を主張しない。

## 確認できた根本原因

1. **worldの法線不一致が手全体を拒否。** `handPose.ts`の `agreement < 0.35` は、正規化画像座標の法線とworld座標の法線の内積で即 `unknown` を返していた。手の甲が写る `4c484f8c-e402-11e8-97db-0242ac1c0002.jpg` の検出結果では内積約−0.723。画像側は背面方向の根拠があり、左右ラベルのscoreも約0.995だが、world情報を渡すだけで全消去された。worldを省くと旧処理でも5本表示できた。
2. **不明と不可視が同一。** `assessNailVisibility()`がunknownに`hardHidden: true`を付け、表示履歴があっても即alpha=0。画面上は手検出成功なので、Canvas全体の表示条件は有効でも、指ごとの描画ループが5本ともskipしていた。
3. **450ms周期で表示開始を永久にリセット。** `NailVisibilityTracker`は前回推論から450ms経過すると状態を空にした。連続して手を検出しても、600ms周期では70msの表示開始待ちが毎回初回に戻り、0→0→0→0本となった。
4. **しきい値の不整合。** 姿勢判定0.6、表示開始0.72が別々に存在し、「back」でも描画不可になる範囲があった。小さい爪のピクセル数から下げた信頼度も、境界検出ではなく基本のランドマーク描画まで消していた。

MediaPipeのworld座標はメートル単位・手の中心原点、画像座標は正規化された投影と相対深度であり、爪の可視性そのものの正解ラベルではない。両者の法線の全面一致を必須条件にしてはいけなかった。[公式の結果仕様](https://developers.google.com/edge/mediapipe/solutions/vision/hand_landmarker/web_js)

左右ラベルと入力画像の反転を組み合わせた既存の符号規約は、今回のテストで逆転原因とは確認されなかった。CSS鏡像の二重反転も再現していない。符号を一律に逆にする変更はしていない。キャッシュが原因であると推測してキャッシュ削除を利用者に要求する修正でもない。

## 最小限の修正

- 手の甲／手のひら／側面の判断は、十分な画像座標側の根拠を優先。worldは方向・一致が確認できたときだけ指の曲げ推定を補助する。不一致・欠落・退化worldは捨てて画像座標に戻る。信頼できないworldで5本をまとめて拒否しない。
- 手の甲の根拠があり各指が見える方向なら、色境界検出がなくても従来のランドマーク配置で表示。手のひらが明確／重なった指などの強い不可視証拠は引き続き非表示。
- 側面／曲げた手のひらの部分描画には、姿勢に加えて現在の画像境界・クリップを必要とする。常にtrueにしたわけではない。
- 不明は `uncertain` とし、不可視の `hidden` と分離。直前に確認済みの手の甲の表示だけを最大350ms維持し、以後は短くフェードアウトする。不明入力で保持期限を延長しない。初回から不明の手を無条件に表示はしない。
- 古い部分描画の絶対輪郭は不明フレームへ持ち越さない。明確な手のひらは保持せず即非表示。
- 状態のリセットは実際のランドマーク喪失・確認された左右切替・新しいカメラセッションで行う。単なる低速推論ではリセットしない。低信頼度／欠落の一時的なhandednessだけでも履歴を消さない。
- 姿勢とランドマーク表示の信頼度を0.6に揃える。これは校正された可視性確率ではない。小さい爪でも1px以上で手の甲の根拠がある場合はランドマークへ戻る。部分境界の採用条件は緩めていない。
- unknownへの一時変化でOne Euro Filterと相対画像補正を全破棄しない。明確な姿勢変化・復帰時の既存の初期化は維持。
- ユーザー向けメッセージも「向きを判断できない」と「爪が見えない」を分けた。カメラを停止させる処理や大規模なUI変更は追加していない。

## 修正前後の再現結果

`git show b2ad626:src/lib/handPose.ts`と`nailVisibility.ts`を一時ディレクトリへ書き出し、現在版と同一データで比較。画像ファイルの代わりに測定済みの21点×画像/world＋左右ラベルを回帰fixtureとして保存した。元写真のピクセルはリポジトリへ追加していない。

| 入力・条件 | b2ad626 | 修正後 |
|---|---:|---:|
| 実画像の手の甲・world不一致 | unknown / 0本 | back / 5本 |
| 同じ実画像でworldなし | 5本 | 5本 |
| 手の甲、600msごとの連続推論 | 0→0→0→0本 | 0→5→5→5本 |
| 正常表示後の一時的unknown | 即0本 | 5本を期限付き維持 |
| 平らな手のひらを表す制御ランドマーク | 0本 | 0本 |

時間系列・裏表の制御ケースは実際の3D回転動画ではない。28枚の補助リプレイの表示数も可視性の正解率として扱っていない。中心誤差・IoU・爪フィット精度の改善を今回の修正結果とは主張しない。

## テストと実ブラウザ

`check-tracking-runtime.mjs`でMediaPipeの戻り値のみを制御し、実際のVIDEO/IMAGE処理→位置推定→画像補正fallback→平滑化→可視性→Canvas描画まで通した。実画像fixture＋600ms周期で5本が継続し、描画では根元影と爪板が各5回実行されることを確認。一時的低信頼度、手のひら、手の甲へ戻す動作、モデル失敗、カメラ切替も維持する。

`check-vanishing-regression.mjs`は次を自動確認する。

- 手の甲5本、明確な手のひら0本、側面の確認済み1本。
- worldなし／不一致／水平反転したworld、左右ラベル、入力鏡像×表示鏡像の全組み合わせ。
- 一時不明・一時的な左右ラベル欠落・期限を超える不明・本当に手を見失った後の再取得。
- 50/200/600/1000msの推論間隔でも表示に到達すること。
- 親指・小指を含む5指、1本だけの不明が他指を消さないこと。
- USB/Webcam設定の非鏡像、フロントの鏡像、リアの非鏡像。

Chrome headlessでは、**実際の同梱MediaPipeと実Canvas**を使用して以下を確認した。静止画をCanvas.captureStreamへ描くカメラ入力であり、MediaPipeの検出結果はstubしていない。

回転の合成ランドマーク検証と、静止画を動かす疑似カメラ検証は別物として記録。物理USBカメラ、実際の手の連続3D回転、iPhone Safari/Android Chrome実機は未検証。最後の参考写真には元々仮想ネイルが重なっているため、正しい爪マスクの評価には使用していない。

## 未検証と公開前確認

個別の実機フレームでモデル自体が左右を誤分類する場合、極端な側面、初回から姿勢不明の場合、曲げた爪の部分可視性はなお限界がある。今回の限定的修正で、あらゆる向き・光・端末で5本を保証するものではない。明確に手の甲と判断できる場面の表示を戻すのが今回のhotfix。

Gitコミットまでで停止し、push・公開はしない。利用者の同じWebカメラで、ローカル最新版の手の甲→横→手のひら→手の甲、近接/遠方、撮影/保存を確認してから公開判断する。
